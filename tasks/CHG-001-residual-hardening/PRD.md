## 1. 目标

消除 CHG-000 审查中记录的 4 项跨平台语义缺陷，使四个脚本在
**Windows PowerShell 5.1/7、Git Bash、Linux、macOS(bash 3.2)** 上行为一致且可预期，
同时不引入新的工具链依赖、不回退已修复项。

## 2. 用户与场景

| 角色 | 场景 | 期望 |
|---|---|---|
| Windows 用户（无 Git Bash） | 首次运行 `ssh-setup.ps1` 生成密钥 | 不被迫手动回车两次；即便降级也不产生带口令私钥 |
| Windows 用户 | `ssh-remove.ps1` 列出连接 | 配置块服务多个别名时能看清全貌，删除影响面与显示一致 |
| Linux/macOS 用户 | `bash ssh-remove.sh` | 正常；`Match` 段存在时不会误删其内容 |
| 任何用户 | 用 `sh` 而非 `bash` 调用 sh 脚本 | 输出无 `-e` 噪声（不误导为脚本报错） |

## 3. 需求与验收标准

### R1 — 多别名单行解析

**需求**：`Host a b c` 应被识别为「一个配置块、三个别名」，列表展示全部别名，
删除该块即删除全部三个别名对应的配置（此为真实语义，不能只删其中一个）。

| AC | 验收标准（可测） |
|---|---|
| AC-1.1 | 对 `Host alpha beta gamma`，列表输出同时包含 `alpha`、`beta`、`gamma` 三个名字 |
| AC-1.2 | 删除该条目后，config 中 `alpha/beta/gamma` 三者同时消失，且其它 Host 块逐字节不变 |
| AC-1.3 | 多别名块中任一名字含 `*` 或 `?` 时，该块被判定为受保护（禁止删除），与 `Host *` 同等对待 |
| AC-1.4 | 单别名场景（既有行为）不得回归：`Host single` 正常列出并删除 |

### R2 — `Match` 块边界

**需求**：`Match` 行必须作为配置块边界处理。删除某个 `Host` 块时，
紧随其后的 `Match` 块内容不得被误删；`Match` 块本身不出现在可删除列表中。

| AC | 验收标准（可测） |
|---|---|
| AC-2.1 | config 含 `Host A` + `Match all` 两段，删除 `Host A` 后 `Match all` 段逐行完好 |
| AC-2.2 | `Match` 段内的行（如 `user foo`）不得出现在列表条目字段中（不污染 Host 解析） |
| AC-2.3 | 被删块**之后**若紧跟 `Match`，`Match` 段保留；被删块**之前**的 `Match` 不得连带删除 |

### R3 — POSIX 输出兼容

**需求**：sh 侧颜色/进度输出改为 POSIX 确定性写法，`sh script.sh` 调用时无 `-e` 字面量。

| AC | 验收标准（可测） |
|---|---|
| AC-3.1 | `sh ssh-remove.sh < /dev/null` 的输出中不出现字面 `-e ` |
| AC-3.2 | `bash` 调用下 ANSI 颜色码仍存在（`\033[` 序列可见），提示可读性不退化 |
| AC-3.3 | 所有用例输出与改动前**文本内容**一致（仅转义机制改变） |

### R4 — 无 bash 通道时的空口令生成

**需求**：Windows 无 Git Bash 时，尝试用 stdin 提供两次回车实现非交互空口令密钥生成；
若实验证明 ssh-keygen 不读 stdin，则保持现状并在文档标注已验证结论。

| AC | 验收标准（可测） |
|---|---|
| AC-4.1 | 存在可复现实验记录：stdin 方式「生效」或「不生效」二者之一，含命令与退出码 |
| AC-4.2 | 若生效：生成的私钥必须能被 `ssh-keygen -y -P ''` 解出（即确为空口令） |
| AC-4.3 | 若不生效：脚本行为与当前版本一致（交互式降级），且注释/文档记录原因 |
| AC-4.4 | 任何情况下不得生成带口令私钥而不告警 |

## 4. 非功能要求

| 维度 | 要求 |
|---|---|
| 兼容性 | PS 5.1+；bash 3.2+；不得使用 bash 4+ 特性 |
| 可回滚 | 每个 milestone 独立可回退；config 改写仍保留时间戳备份 |
